# For LLM agents

## Starting prompt

`llms.txt` is the file to hand a coding agent. It covers the working setup, the rules that are easy to
get wrong, every entry point, every component with its import path and sizing behaviour, the shared
config types, the export API, and a symptom-to-fix table, all in one self-contained file. Its tables
come out of the source and cannot fall behind the code.

The file is published inside the npm package. An agent with the dependency installed already has it:

```
node_modules/@r4pm/components/llms.txt
```

## What to point an agent at

| Question | Source |
| --- | --- |
| How do I set this up, what exists, why is it blank? | `llms.txt` |
| Exact props of one component | its Storybook page, generated from the TypeScript types |
| Exact shape of a `data` prop | [Data Types](?path=/docs/getting-started-data-types--docs), generated from the Rust bindings |
| A runnable example | the "Full example" block at the bottom of each component page |

## Rules worth putting in a system prompt

| Rule | Why |
| --- | --- |
| Wrap the app in `<Theme>` and import `@r4pm/components/styles.css` once | without it components render with layout and no styling |
| Give graph viewers `viz` (e.g., `wasmViz`) through `ViewerConfigProvider` | the core does not include it, so nodes sit in a plain row or column |
| Give graph viewers a parent with a definite height | their root is `height: 100%` and collapses in an auto-height parent |
| Wrap anything exportable in `<ViewerExportFrame>` | it is the only export control in the package |
| Import UI primitives from `@r4pm/components/ui`, never `@radix-ui/themes` | the package lints this |
| Memoize anything passed into `ViewerConfig` | a new identity every render makes viewers restyle and relayout |
